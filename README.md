# Scarce Item Queue — авторский код

Персональная подборка кода, который я написал для сервиса очереди на дефицитные товары.

В репозитории намеренно нет полной копии командного проекта: общие файлы и код других участников исключены. Поэтому эта подборка показывает мои технические решения, тесты и продуктовые расширения, но не собирается как самостоятельное приложение без базового командного проекта.

Автор: [Никита Поздняков — cunofou](https://github.com/cunofou).

## Мои зоны ответственности

- PostgreSQL и защита конкурентных операций от oversell.
- E2E и acceptance-проверки бизнес-инвариантов очереди.
- AI-рекомендации похожих товаров и бесплатный catalog fallback.
- Адаптивный размер очереди на основе метрик успешности и конверсии.
- Безопасная demo-оплата и повторный покупательский сценарий.
- Grafana dashboard и проверки observability-конфигурации.
- Backend hardening и защита внутренних изменяющих маршрутов.

## Содержимое

### Адаптивная очередь

`internal/adaptivequeue`, `internal/pkg/domain/waiting_buffer.go` и HTTP handler содержат контроллер, который меняет waiting buffer только при достаточной выборке и ограничивает диапазон и скорость изменения.

### Рекомендации

`internal/recommendation/openai`, recommendation repository, PostgreSQL/pgvector реализация и миграции показывают semantic-поиск, кэширование embeddings и детерминированный fallback без внешнего API.

### Demo-покупка

Backend handler, frontend API/hook/button и тесты показывают положительное завершение checkout без интеграции с настоящим платёжным провайдером.

### Проверка бизнес-логики

`internal/e2e` содержит acceptance и E2E-сценарии для FIFO, TTL, идемпотентности, оплаты, восстановления ёмкости и конкурентных запросов.

### Наблюдаемость

`loadtest/grafana` и `internal/loadtest/grafana_test.go` содержат первоначальную авторскую версию provisioned dashboard и автоматические проверки его структуры.

## Что я защищаю на финале

1. Почему транзакционная блокировка товара и ограничения PostgreSQL не позволяют продать одну единицу несколько раз.
2. Как временное персональное право связывает пользователя, товар, состояние и TTL.
3. Как тестами подтверждаются FIFO, идемпотентность и корректность при конкурентных запросах.
4. Как рекомендации удерживают пользователя, даже если исходный товар закончился.
5. Как метрики и адаптивный buffer позволяют развивать очередь на основе реальной конверсии.
